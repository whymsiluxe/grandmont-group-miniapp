## ПРИОРИТЕТ 2 — конкретные баги, описаны owner с точным репро

### 3. Team-add popup появляется с задержкой ~1сек (регрессия после фикса display:none)
Коммит 328ed68 исправил сам факт что popup не появлялся (.bottom-sheet-overlay.open
теперь ставит display:flex). Owner сообщил после этого что popup стал появляться,
но с заметной задержкой ~1 сек, чего раньше не было (до фикса баг маскировал задержку,
т.к. вообще не показывался). НЕ диагностировано. Живая диагностика: замерить время
между click и appearance overlay (аналогично тому как замеряли composer -- pointerdown
timestamp vs первый кадр где overlay реально viewport-visible). Вероятные причины:
(a) `/api/objects` fetch внутри teamAddBtn click handler (object-info.js:~154) блокирует
открытие -- если так, открывать overlay СРАЗУ (пустой/skeleton), резолвить objectName
асинхронно, не ждать fetch перед первым рендером; (b) CSS transition на .bottom-sheet-overlay
opacity (220ms) + .bottom-sheet-panel transform (240ms) складываются с чем-то ещё.
Смотреть код в assignment-sheet.js `_asRender()` и object-info.js team-add handler
(секция "team-add button handler" в этом файле).

### 4. Task-note textarea в Assignment Sheet — тот же keyboard-lag, другой компонент
Owner описал: "поднимается клавиатура потом поднимается поле ввода над ней" — на

`_asTaskNoteStepHtml`). Это НЕ #view-chat/#view-ai (composer-фикс туда не относится) --

вообще, статичный vh-юнит, который не сжимается под клавиатуру в Telegram fullscreen).
Нужна СВОЯ живая диагностика (не переносить бездумно chat-фикс) -- этот компонент
проще (одна textarea, не список из сотен сообщений), возможно подойдёт простой CSS
через var(--tg-vp-height) на max-height вместо vh, раз здесь нет большого DOM-дерева
и потому нет риска layout-thrash что был в чате. Замерить сначала, не гадать.
